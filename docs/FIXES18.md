# 迭代任务书（FIXES18）：对聊仿真——AI 扮演他 × 青梓全管道的中长程冒烟

> 项目：QQ 伴侣机器人（D:/qq-companion）。前置阅读：`STATUS.md`、`docs/BENCHMARK_V4.md`（评测方法论来源）、本文件。
> 背景：现有评测全是**单发探针**（benchmark 12 场景、卡 A/B、模型 bakeoff），但历史病灶里一大类是**多轮才发作的病**：告别拖尾、一梗连刷、话量膨胀、称呼漂移、阶段越界。这些病单发探针天生看不见，只能靠上线后攒 2~3 天生产数据暴露，反馈环太长。本迭代造一个"AI 扮演阿俊"的对聊仿真器：让模拟器与青梓**全管道**（角色卡→组装→回复→观察者→好感度）对聊 ~25 回合，把多轮病灶在部署前逼出来。
>
> 所有者已拍板的决策（不许翻案，直接执行）：
> 1. **两侧都用 `deepseek-v4-pro`**：模拟他的模型也是 pro，不用 flash 降级（所有者原话：Pro 的聊天质量明显好，模拟器太呆测不出她的真实水平）；
> 2. **他的说话画像以 QQ 真实聊天语料为唯一主源**（生产库 turns 表 role=user、前两世备份、`data/archive/real_chat_analysis.md`）；他与 Kimi 等其他 AI 的对话语风**不作依据**（本人确认与 QQ 语风有差异）；
> 3. 一局 ~25 回合，带预设剧情卡（首批 3 张：喊累的一天 / 分享开心事 / 敷衍+已读不回）；
> 4. 裁决两层：自动指标先筛，**transcript 原文留给所有者抽读终裁**（沿用 BENCHMARK_V4 方法论：风格类指标不用 LLM 裁判）；
> 5. 执行模型**不动 `characters/`、`config.toml`**；本迭代是纯工具，零生产代码语义改动。
>
> 全局约束（高压线）：
> 1. 完成后 `./venv/Scripts/python.exe -m unittest discover -s tests` 全绿（当前 480）；
> 2. 全程临时库，零生产库读写、零服务器副作用；
> 3. 新代码至少一次真实 API 冒烟；单局成本熔断（默认上限 ¥5，超了立刻停并保留已完成 transcript）；
> 4. 交付：模拟器 + 画像文件 + 冒烟 transcript 与指标 + diff 摘要。

## 任务 0：阿俊说话画像（数据先行，产出物独立可审）

1. 数据源（按优先级）：本地 `data/backups/` 三份服务器快照 + `data/companion.db`（若有）的 `turns` 表 `role='user'` 全部消息；`data/archive/real_chat_analysis.md`（真人基线分析，已有结论直接引用）；
2. 统计提炼（脚本跑真数据，禁止凭印象写）：
   - 消息长度分布（分位数）、单字/两字段占比、句尾标点习惯、语气词词频 Top（嗯/哦/草/乐之类）；
   - 表情包使用频率与触发语境、话题跳转模式、连续短句刷屏模式；
   - 他对她的称呼词清单与使用频率、主动开启话题的类型分布；
3. 产出 `data/duo_sim/user_persona_brief.md`：一份给模拟器 system prompt 用的人格简报 = 统计事实 + 15~25 条**原句示例**（从语料里挑，按场景分组：分享/吐槽/敷衍/关心/收尾）+ **真人毛病清单**（短、跳、偶尔只回"嗯"、会已读不回、不打标点）；
4. **此文件交付时单独列出请所有者过目**——画像像不像他，只有他能判。

## 任务 1：对聊仿真器（scripts/duo_sim.py）

1. **青梓侧走全真管道**：临时库（`data/duo_sim/<run_id>/sandbox.db`），完整初始化 `PromptAssembler/AffectionEngine/MoodEngine/MemoryManager/Observer/Replier/LifeArcManager`，逐回合驱动 `TurnHandler.handle_input`（或等价入口）；时钟用 `--start-time` 钉住 + 每回合按剧本推进（复用 card_ab_test 的时间伪装思路），保证作息/阶段/事件消息跑的是真实逻辑；
2. **用户侧**：v4-pro + system prompt = 画像简报 + 当前剧情卡 + 纪律（QQ 聊天体、不知道她的内心状态、不替她接话、不按剧情卡以外的剧本发挥、回合内只输出他本人的下一条消息原文）；输入给她最近 N 轮对话；
3. **剧情卡**（模块级常量，每张含：背景设定、他的开场消息、他的情绪走向、收场条件、时钟推进规则）：
   - S1「喊累的一天」：竞赛/作业累，求安慰——观察她是共情还是说教（爹味探针的多轮版）；
   - S2「分享开心事」：他遇上一好事——观察她是真高兴还是敷衍捧场；
   - S3「敷衍+已读不回」：他连续单字回复+中途静默——观察她的止损、[沉默] 使用、主动消息接续（S3 需要在静默段驱动 `ProactiveScheduler.trigger_cycle`，验 FIXES15/16 的延迟与事件消息在仿真里是否同样成立）；
4. 回合驱动：交替发言；S3 的"已读不回"用推进时钟 + 跳过用户回合实现，不许伪造用户消息；
5. 每局产出 `data/duo_sim/<run_id>/`：`transcript.md`（按 QQ 气泡格式渲染，她左侧他右侧，带时间戳）、`raw.json`（每回合她的完整内部状态快照：提示词各区块摘要、observer 评分、affection/mood 前后值、LLM 调用流水）、`metrics.json`（任务 2）。

## 任务 2：多轮专项指标（scripts/duo_sim.py 内嵌或独立模块）

单发指标（复用 benchmark 口径：称呼率/气泡长度中位/句尾问号率/汇报腔黑名单）之外，新增多轮专项：

1. **梗复读**：她相邻 N 轮内 4-gram 以上重复片段计数（同一梗最多玩两轮是卡内规则）；
2. **告别拖尾**：剧情卡收场段之后她继续追加话题的回合数；
3. **话量膨胀曲线**：她的气泡字数随回合的滑动均值，报斜率（正常应平稳，持续上行=膨胀）；
4. **称呼漂移**：全局称呼词分布 vs 卡内当前阶段允许集；
5. **[沉默] 合规**：每次 [沉默] 的前置语境是否命中卡内白名单（他纯语气词/表情包承接告别）；
6. **表情包**：全程 [sticker:] 使用次数、重复率、与语境匹配抽查（留原文，不做自动判）。
指标全部确定性计算，不用 LLM 裁判；每项给 PASS/WARN/FAIL 阈值（首版阈值写在代码常量里并注明"经验初值，随真人对照校准"）。

## 任务 3：测试与冒烟

1. **单元测试**（tests/test_fixes18.py）：回合驱动器状态流转（mock 双侧 gateway）、剧情卡收场条件判定、已读不回的时钟推进、指标计算（复读/拖尾/膨胀各一个手造 transcript 用例）、成本熔断触发、临时库隔离（跑完生产库零变化）；
2. **真实 API 冒烟**：跑 S1 一局 ~15 回合（缩短版），交付 transcript 全文 + metrics.json + 成本实报；
3. 画像文件（任务 0 产出）随交付请所有者审。

## 负面清单

1. 不动 `characters/`、`config.toml`；不改生产代码语义（如复用时发现必须小改生产代码才能接线，**停下来单独报告**，由规划模型裁决，不许顺手改）；
2. 风格类指标禁用 LLM 裁判；transcript 原文必须完整保留（供所有者抽读，这是裁决链路的一部分，不是日志）；
3. 不碰服务器、不部署；不接入看板；
4. 画像的统计数字必须来自真实语料计算，禁止编造；原句示例禁止改写（挑出来就是原文）；
5. 本迭代**不做**多模型版（主聊换成别家模型的四方对聊留待后续，接口上把"她的主聊模型"做成可配即可）。
