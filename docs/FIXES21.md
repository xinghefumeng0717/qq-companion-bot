# 迭代任务书（FIXES21）：引用回复发送侧——她能指着他某句话回话

> 项目：QQ 伴侣机器人（D:/qq-companion）。前置阅读：`STATUS.md`、本文件；收侧引用实现 `companion/onebot.py` 的 `_fetch_reply_context`；发送链路 `companion/main.py` 的 `_send_chunk_to_onebot`。
> 背景：**收侧引用早就支持**（他引用她的消息，她能看到「（他引用了你之前说的「XXX」）」前缀），但**发侧是单向街**——她从没引用过他的话。他连发三条消息、她回应其中第一条时，没有引用指代全靠语境猜；隔了几个话题回应旧事时更明显。真人聊天里"引用"是低频率但高信息量的动作，缺了它对话的指代精度差一截。
>
> 所有者已拍板的决策（不许翻案，直接执行）：
> 1. 引用是**低频高精度**动作：大部分回复不引用，只在"指代不明"时用（他连发多条她回较早的一条 / 跨话题回应旧事）；机制层硬上限**每轮最多 1 条引用**；
> 2. 只许引用**本轮聚合批次内**的消息（防她引用三天前的话——那种用法真人几乎不用，且 message_id 链路只管得到近处）；
> 3. **施工时机：FIXES20（QQ 表情双向）交付后再开工**——两单同改 `replier.py`/`main.py`/`prompts.py`，并行必撞车，本单排队；
> 4. 执行模型**不动 `characters/`、`config.toml`**。
>
> 全局约束（高压线）：
> 1. 完成后 `./venv/Scripts/python.exe -m unittest discover -s tests` 全绿（当前 575+FIXES20 新增）；
> 2. 新代码至少一次真实 API 冒烟；
> 3. 交付：逐项 diff 摘要 + 测试输出 + 冒烟证据。

## 任务 1：message_id 链路（onebot.py → aggregator.py → turn_handler.py）

1. 入站事件本就有 `message_id`，但聚合器目前只留文本——把每条入站消息的 `message_id` 随文本一起穿过聚合器（聚合批次里每条消息保留 id + 文本 + 时间），送到 `TurnHandler`；
2. 聚合批次内多条消息合并时，**编号与 id 的映射**要保留（模型看到的 [1][2][3] 编号 ↔ 真实 message_id）；
3. 语音/图片等非文本消息同样保留 id（她也可以引用一张图回话）；
4. 链路任何一环取不到 id（历史消息、回声、异常）→ 该消息不可被引用，降级不影响主流程。

## 任务 2：`[quote:N]` 语法与提示词（replier.py + prompts.py + turn_handler.py）

1. **输入侧**：组装提示词时，把本轮聚合的消息按 `[1] 文本 / [2] 文本` 编号呈现（编号样式参照现有「他引用了…」前缀的写法，保持模型读起来自然）；
2. **输出语法**：她想引用时输出 `[quote:2]`，必须是一行的开头（引用是"回哪句"的指代，位置固定在回复头部）；`parse_reply` 识别并转成 `{"type": "quote", "index": N}` chunk；
3. **校验与降级**：编号超出本轮批次 / 不是合法数字 / 出现在行中或行尾 → 按普通文字处理（降级不炸）；每轮只保留**第一个** quote chunk，多余的降级为文字；
4. 提示词纪律（`SYSTEM_PROMPT_TEMPLATE` 补一句，参照既有单句规则风格）：`大部分时候直接回就好；只有他连发多条、你在回应其中较早的一条，或隔了话题回应旧事时，才在回复开头写 [quote:编号] 引用——引用是为了指代清楚，不是为了形式`；
5. 主动消息（proactive）**不支持**引用（没有对方消息可引）——`source="proactive"` 时 quote 语法一律按文字降级。

## 任务 3：发送（main.py `_send_chunk_to_onebot`）

1. quote chunk 不单独发：拼接到**紧随其后的第一个 text/face 消息**的段数组头部（OneBot `reply` 段 + 原文段，一条消息出去）；
2. quote 后没有任何正文（模型只输出了 [quote:N]）→ quote 降级丢弃，不空发；
3. NapCat 对 reply 段的失败（id 过期/不支持）→ 去掉 reply 段重发正文，消息不丢；
4. typing 表演（FIXES15）不受 quote 影响（quote 不算文字量）。

## 任务 4：测试与冒烟

**单元测试**（tests/test_fixes21.py）：message_id 穿链（入站→聚合→编号映射）；`[quote:]` 识别（行首合法/行中降级/编号越界/非数字）；每轮上限 1 条；quote+text 合并发送的段数组结构；quote 无正文丢弃；reply 段失败重发正文；proactive 通路降级；与 FIXES20 face 段同轮共存（quote+文字+face 一条消息的段顺序）。

**真实 API 冒烟**（scripts/smoke_fixes21.py）：
- A 段：模拟他连发 3 条（mock 进站、真实管道），其中第 1 条埋一个需要回应的点，贴出她的回复——命中引用时贴 OneBot 出站报文（reply 段 id 与第 1 条消息 id 一致）；
- B 段：对聊仿真跑一局（S2 卡，模拟器连发习惯会自然制造场景，¥0.5 内），统计她的引用次数与命中率——验收标准：**引用率低（多数轮次不引用）但命中场景时不缺位**。
