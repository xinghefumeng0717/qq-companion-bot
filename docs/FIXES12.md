## 生产证据（执行模型必读）

**E8（"[图片]"泄漏，10-04 09:19）**：主动消息实际发到 QQ 的内容是
```
临湖今天人少，窗边位不用抢，早午餐给你看下
[图片]
你上次不是问哪个窗口人少才肯动身嘛，这会儿在家早餐吃了吗
```
第二行是字面量 `[图片]`，被当普通文字发出。事故链（bot.log 实锤）：欲言又止池残留念头"想拍张临湖餐厅的菜发给他"（**她没有摄像头，这是不可能任务**）→ 09:18:43 决策层选它为 topic_hint（原话"拍一张临湖早午餐的照片发给他"）→ 生成层硬着头皮输出 `[图片]` 占位符。

**E9（表情包社交语义丢失，10-04 10:03）**：他回了一张"嗯嗯"抖动表情包（对话收尾信号），视觉描述却是"白色卡通小动物，紫底，头顶有'嗯嗯'抖动符号，带腮红，表情乖巧"——纯客观画面，**社交含义被过滤**。于是她接了一句"我发现了/你安静下来的时候/就爱发这种软乎乎的表情/收拾完了？"继续抛问题，对话该断不断。根因：视觉提取指令（`companion/turn_handler.py:68` 附近硬编码）写的是"客观描述画面即可"。

## 任务 1："不能拍照"规则入提示词 + `[图片]` 占位符发送滤网（P0，证据 E8）

**规格**：

1. **主聊提示词**（`companion/prompts.py` `SYSTEM_PROMPT_TEMPLATE` 的表情包行，当前原文为
   `可发送表情包：在需要时于消息中单独一行输出 [sticker:描述词]（可用描述：{stickers_list}），不要滥用，整轮最多一次。`）
   在该行末尾追加一句（不改原句）：
   `你不能拍照，也无法发送真实照片；[sticker:描述词] 是你唯一的发图方式，绝对不要输出 [图片]、[照片] 这类占位符。`
2. **主动消息决策层**（`PROACTIVE_DECISION_PROMPT`）：在分支说明区追加一条：
   `注意：她不能拍照或发送真实照片，topic_hint 不要包含"拍照片/拍张照发给他"这类不可执行的计划；想分享场景就用文字描述。`
3. **主动消息生成层**（`PROACTIVE_GENERATE_PROMPT`）：【要求】区追加一条：
   `你不能拍照或发真实照片；唯一的发图方式是单独一行 [sticker:描述词]；绝对禁止输出 [图片]、[照片] 这类占位符。`
4. **代码滤网**（`companion/replier.py`）：在 `parse_reply` 的文字段处理环节，丢弃**整行就是**占位符的行——匹配模式（去掉首尾空白后整行匹配）：`[图片]`、`【图片】`、`[照片]`、`【照片】`、`[image]`（大小写不敏感）。只丢这种"整行占位符"，行内夹杂其他文字的一律保留。丢弃时记 INFO 日志（内容+来源）。位置在切句之前、sticker 拆分之后；落库 record 由最终实发段反推的逻辑不变（被滤掉的行本就不该落库）。
5. **不做**：不改欲言又止池的生成/淘汰机制；不追溯清理存量 desires（池子 48h 自洁+用完即删，会自愈）；不改 `[sticker:...]` 解析与匹配逻辑。

**测试**：
- 滤网：4 种占位符整行被丢（含大小写变体如 `[IMAGE]`）；`今天[图片]里那只猫真好玩` 这类行内出现的保留；丢弃后 record 与被滤内容无关；
- 三个提示词模板各含新句子（assert 子串即可）；
- 现有 replier/proactive 测试全绿。

## 任务 2：视觉描述补"社交语义"（P1，证据 E9）

**病灶**：`turn_handler.py` 视觉提取的用户指令为硬编码字符串 `简明描述这张图片的关键内容、场景与细节（50字以内，客观描述画面即可）：`。"客观描述画面"把表情包/梗图的社交功能（收尾、同意、撒娇、无语）系统性滤掉了，主聊模型拿到的只有视觉元素。

**规格**：

1. 把该硬编码字符串提取为 `companion/prompts.py` 中的模块级常量 `VISION_PERCEPTION_PROMPT`，文案改为：
   ```
   简明描述这张图片（60字以内）。如果是普通照片，客观描述关键内容与场景即可；如果是表情包或梗图，除画面外务必点明它传达的情绪或聊天含义（例如"表示同意/收尾""撒娇""无语""调侃"），因为这决定了对方该如何接话。
   ```
   `turn_handler.py` 改为从 prompts 导入该常量，调用处其余逻辑（截断 120 字、降级占位符、purpose=`vision_perception`）一律不动。
2. **不做**：不改两段式视觉架构（flash 描述→注入 pro 的承重墙原样）；不改 `stickers.py` 的表情包打标提示词（`STICKER_DESC_PROMPT` 是收藏打标用，场景不同）；不改图片大小/格式限制。

**测试**：`turn_handler` 导入处引用的常量与 prompts.py 一致（assert 同源）；常量文案含"表情包"与"情绪或聊天含义"关键词；现有视觉相关测试全绿（如有 mock 断言旧文案的，同步更新并注明原因）。
