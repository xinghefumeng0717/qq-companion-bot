# 迭代任务书（FIXES20）：QQ 系统表情双向——她能看见他的狗头，也能偶尔丢一个回去

> 项目：QQ 伴侣机器人（D:/qq-companion）。前置阅读：`STATUS.md`、本文件；盲区证据 `companion/onebot.py` 的 `_extract_message_text`；他的表情使用习惯证据 `data/duo_sim/user_persona_brief.md` 第 1.4 节（微信语境）。
> 背景：两件一件事。**收侧是 bug 级感知盲区**：`onebot.py` 的消息文本提取只保留 `text` 段，`face`（QQ 系统表情/小黄脸）段被**静默丢弃**——他发"你真棒[旺柴]"，她只收到"你真棒"，语气全断。他的语料里 22.5% 的消息带表情标签（[晕]×468/[捂脸]×367/[旺柴]×142），这些是他的主要语气标记，盲区每天都在生效。**发侧是配套能力**：她目前只会发大表情包（图片），不会用他语言习惯里最高频的小黄脸——对话质感"干巴巴"（所有者原话）。
>
> 所有者已拍板的决策（不许翻案，直接执行）：
> 1. **双侧都做**（所有者原话："我希望不要只做收侧的，两侧都要做"）；发侧不必等生产数据积累——FIXES18 对聊仿真器就是验收裁判；
> 2. 收侧把 face 翻译成**方括号文字标签**（`[旺柴]` 这种，与他聊天语料形态一致，模型读起来零障碍），按消息段原始顺序插入文本流；
> 3. 发侧的核心约束是**"偶尔"**（所有者原话："偶尔发一个，不是句句带脸"）：机制层硬上限（每轮 face ≤2、同气泡 ≤2——刻度按他真实使用数据定，见任务 3 引注）+ 提示词层纪律约束；
> 4. **不只狗头**（所有者原话）：收侧映射做 QQ 系统表情**全集**，发侧可用清单只放高频精选；
> 5. 执行模型**不动 `characters/`、`config.toml`**；发侧纪律写在 `prompts.py` 系统模板，不进角色卡。
>
> 全局约束（高压线）：
> 1. 完成后 `./venv/Scripts/python.exe -m unittest discover -s tests` 全绿（当前 575）；
> 2. 新代码至少一次真实 API 冒烟；
> 3. 交付：逐项 diff 摘要 + 测试输出 + 冒烟证据。

## 任务 1：face/mface id→标签映射表（companion/onebot.py 或新模块）

1. 建模块级常量 `QQ_FACE_TAGS`：`face id → 中文标签名`（如 `337 → "旺柴"`），**覆盖 QQ 系统表情全集**，来源用 NapCat/go-cqhttp 公开的 id 表（注释注明出处与抓取日期），禁止凭记忆手填 id——必须从可核验的公开定义抄；
2. 未知 id 降级为 `[表情]`，不炸、不丢消息；
3. `mface`（商城/大表情）段：优先用段内 `summary` 字段（QQ 自带形如 `[狗头]` 的摘要），取不到降级 `[大表情]`。

## 任务 2：收侧修复——face 段进文本流（onebot.py `_extract_message_text`）

1. 遍历消息段时**保持原始顺序**：text 段照拼，face 段插入 `[标签]`，mface 段插入其 summary 标签；最终效果："你真棒" + face(旺柴) → `"你真棒[旺柴]"`；
2. 纯 face 消息（整串没文字）也得到 `[旺柴]` 而不是空串——**注意排查下游对空文本的假设**（聚合器是否跳过空消息、observer 对纯标签消息的语义，逐项确认不炸；纯标签消息语义浅是事实，允许 observer 给低分，不许崩）；
3. 引用消息描述（`_quoted_media_desc`）里 face 的归类不动（仍算"一张图"那边的逻辑若存在，维持原状——只改文本提取）；
4. 落库形态说明：标签随文本进 turns 表，日记/observer/欲言又止全链路自然可见——这是目的不是副作用。

## 任务 3：发侧——她输出 `[face:标签]`（replier.py + onebot 发送链路 + prompts.py）

> 发法形态以他的真实使用数据为设计图（微信语境，`data/duo_sim/face_usage_stats.json`）：
> 带表情消息里 65% 是"文字+表情同气泡"（其中 97% 表情挂在句尾）、35% 是纯表情气泡；
> 纯表情气泡中二连 107 条（同款二连 [旺柴][旺柴] 121 条）、三连 21 条；
> "文字气泡后 60 秒内紧跟纯表情气泡"245 次。**她必须能复现这三种发法。**

1. **输出语法**：显式段语法 `[face:旺柴]`（与 `[sticker:]` 对称，不用裸 `[旺柴]`——裸标签会和他自己发的文本撞车，无法区分"她说要写给他看的字"和"她要发的表情"）；
2. `parse_reply` 识别 `[face:标签]` 段，转成 `{"type": "face", "tag": ...}` chunk；**白名单校验**：标签必须在她可用清单内（任务 4），不在清单内的按普通文字原样发出（降级不炸）；
3. **混排合并（主形态，必须做对）**：行内"文字 + `[face:]`"混排时，发送端要把 text 段与 face 段**合并进同一条 QQ 消息**（OneBot 允许一条消息混合 text+face 段），而不是拆成两个气泡——"你真棒[旺柴]"是一个气泡，不是"你真棒"+"[旺柴]"两条；
4. **频率硬上限（机制层，按他的数据定刻度）**：每轮 face 总数 **≤2**、同一气泡内 face **≤2**（他的纯表情气泡 92% 是 1~2 个，同款二连合法、三连罕见）；超出部分按普通文字降级；face 与 sticker 可同轮共存（一个是语气一个是图，不互斥）；
5. 发送链路：`main.py _send_chunk_to_onebot` 增加 face 类型 → OneBot `face` 消息段（用标签名反查 id 表）；反查不到的兜底按文字发；一条消息内 text 与 face 段并存的组装按 OneBot 消息段数组实现；
6. **typing 表演兼容性**（FIXES15 已上线逻辑）：face chunk 的文字量按现有 sticker 的折算方式处理，不让一个表情触发长 typing；
7. **与既有滤网的顺序**：face 段识别在整行滤网（FIXES19/12）之后、切句逻辑的配合关系照 `[sticker:]` 的现有模式办，推导清楚写进 commit message（DEEP_AUDIT 面 A-8 的同一把尺）。

## 任务 4：她的可用清单与纪律（prompts.py）

1. `SYSTEM_PROMPT_TEMPLATE` 与 `PROACTIVE_GENERATE_PROMPT` 的表情包说明段各补一段（参照 FIXES17"括号内是含义"的写法）：
   - 可用 face 清单：**从全集挑 20~30 个高频精选**（选择依据=他语料词频 Top（晕/捂脸/好的/旺柴/憨笑/流泪/苦涩/耶/惊讶/破涕为笑/嘿哈/机智，微信语境）与 QQ 小黄脸实际可用集的交集，注释注明来源；QQ 没有对应项的用通用高频补上）；
   - **清单带含义标注（与 FIXES17 同名同药："名称（含义/使用时机）"）**：标注口径以他的真实用法为准（抽样依据如下，写注释里），不是词典释义——
     - `[旺柴]`＝狗头保命：说完反话/口嗨/调侃后挂上，表示"别当真"；
     - `[晕]`＝无语、服了、我人没了（对离谱事或对自己犯蠢）；
     - `[捂脸]`＝哭笑不得、自嘲式尴尬；
     - `[流泪]`＝卖惨自嘲（学习/工作太累）；
     - `[好的]`＝收到、应承（常单发，等于 OK）；
     - 其余清单项照此风格标注（每个一句话："表达什么 + 什么时候用"）；
   - **读侧词表（同一份标注的另一半用途）**：系统提示词里加一句"他消息里 `[xx]` 是 QQ 表情，含义见清单"——她**读**他的狗头时用同一份口径，双向单一数据源；
   - 纪律写死：`偶尔用——按语境自然出现时用，不要句句都带；可以挂在句尾、也可以单独发一个；同一件事最多发两个；[face:] 里只写清单内的标签名`；
2. 清单做成模块级常量 `PROMPT_FACE_LIST`（与贴纸清单同款维护方式），replier 白名单、读侧词表与提示词共用这一份，单一数据源。

## 任务 5：测试与冒烟

**单元测试**（tests/test_fixes20.py）：
- 收侧：face 段转标签且保序（文字+face+文字混合）、纯 face 消息不空串、未知 id 降级、mface summary 优先、下游空文本假设排查的回归（聚合器/observer 喂纯标签不炸）；
- 发侧：`[face:]` 识别与 chunk 结构、白名单外降级文字、每轮硬上限 1 个、face+sticker 同轮共存、与滤网链的顺序推导用例、提示词含清单与纪律句；
- 全部本地构造，禁止真实 API。

**真实 API 冒烟**（scripts/smoke_fixes20.py）：
- A 段（收侧）：构造含 face 段的 OneBot 消息（mock 进站）走真实 turn 管道，贴出她收到的文本与她针对狗头语境的回复（重点：她能不能读懂"你真棒[旺柴]"是损不是夸）；
- B 段（发侧）：对聊仿真跑一局（S1 或 S2 卡，¥0.5 以内），统计她的 face 使用次数/形态分布（混排句尾 / 纯表情气泡 / 同款二连各占多少），贴 transcript 里用到 face 的片段——验收标准：**三种发法都出现过或出现得自然、每轮 ≤2 个、全局不刷屏、语境贴合（被损时回 [旺柴] 类而不是 [流泪] 类）**；
- C 段（发送结构）：真实发送管道到 mock OneBot，验证 face 段的 OneBot 报文结构正确。
