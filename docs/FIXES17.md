# 迭代任务书（FIXES17）：表情包语义重标注（三栏标注 + 所有者审核 + 打标规则换代）

> 项目：QQ 伴侣机器人（D:/qq-companion）。前置阅读：`STATUS.md`、本文件。
> 背景：所有者实测确诊——表情包"很假"的病根在标注：现有标注是视觉模型自动打的**画面描述**（"白色卡通小动物、紫底、带腮红"），她选表情包时只能按画面贴话题，而表情包真正的货币是**语用功能**（这张图是"干饭/撒娇/无语"）。典型案例：大鲸鱼吃白米饭那张，画面标注完全丢失了"干饭"语义。本迭代把库存表情包全部重打标为三栏（画面/含义/适用场景），**所有者真人审核**后入库，并同步换代新表情包的自动打标规则。
>
> 所有者已拍板的决策（不许翻案，直接执行）：
> 1. 标注三栏制：**画面**（一句话）+ **含义**（语用/情绪功能，如"表示干饭，带委屈的炫耀"）+ **适用场景**（"聊到吃饭/喊饿时用"）；
> 2. **两段式施工**：第一段执行模型批量打标并生成审核表 → **停工等所有者审核**（所有者直接改审核表文件）→ 第二段应用入库。执行模型不得跳过审核直接入库；
> 3. 审核对象必须是**服务器上的当前生产表情包库**（运行时收藏会增量，先拉回再标），不是本地的种子库；
> 4. 执行模型**不动 `characters/qingzi/character.json`、`config.toml`**；`characters/qingzi/stickers/index.json` 的修改只许走"所有者审核后的审核表应用"这一条路。
>
> 全局约束（高压线）：
> 1. 完成后 `./venv/Scripts/python.exe -m unittest discover -s tests` 全绿；
> 2. 真实 API 调用仅限标注与冒烟，零服务器写操作（拉库是只读 scp 下载）；
> 3. 交付：审核表文件 + 应用后的 diff 摘要 + 测试输出。

---

## 任务 0：摸底盘点（先做，结果写进交付摘要）

1. 【本地电脑执行】从服务器拉回当前生产表情包库到 `data/sticker_audit_workdir/`（只读 scp，命令规范见 AGENTS.md）；
2. **查明 DB `stickers` 表（57 行）与 `stickers/index.json`（42 键）的关系与漂移**：哪个是 `get_prompt_sticker_list()` 的真实数据源、两边差集是什么（生产实测两边数量不一致，必须解释清楚再动手）；结论写进交付摘要。若发现收藏写入路径存在双写不一致，**只记录报告，不在本迭代修**（另立项）。

## 任务 1：批量重打标（scripts/relabel_stickers.py）

1. 输入：任务 0 拉回的 workdir（图片 + index.json）；
2. 对每张图：视觉模型（flash，vision）按三栏提示词直接输出 JSON：`{"画面": "...", "含义": "...", "适用场景": "..."}`。提示词要点（写死）：
   - 含义栏必须回答"发这张图的人在表达什么情绪/态度"，禁止只描述画面元素；
   - 适用场景栏必须回答"什么聊天语境下发这张合适"，给 1~2 个具体语境；
   - 画面栏一句话，不超过 20 字；
   - 示意示例放在提示词里（如：大鲸鱼吃白米饭 → 画面"鲸鱼端着饭碗扒饭"，含义"干饭/饿死了，带一点委屈的炫耀"，适用场景"聊吃饭、喊饿、晒食堂时用"）；
3. 输出审核表 `data/sticker_audit.md`：Markdown 表格，列 = 名称 | 画面 | 含义 | 适用场景 | 旧标注（对照），每行可编辑；文件头写明审核方法（"直接改表格里的字，改完说一声"）；
4. 跑完打印成本与失败清单（个别图标注失败允许，列入表尾"待人工"区）；
5. **到此停工**，在交付摘要里明确提示所有者审核 `data/sticker_audit.md`。

## 任务 2：应用入库（scripts/apply_sticker_audit.py，所有者审完后才跑）

1. 解析所有者改过的 `data/sticker_audit.md`，容错：解析不了的行跳过并列清单，绝不猜；
2. 写回 **index.json**：每个键扩展为 `{"file": ..., "desc": 旧画面描述, "meaning": 含义, "usage": 适用场景}`（保留 desc 字段兼容，新增 meaning/usage）；审核表中"待人工"区或所有者留空的行保持原样不动；
3. 若任务 0 查明 DB stickers 表也是提示词数据源，同步更新对应字段；不是则不动 DB；
4. 写回前自动备份原 index.json 到同目录 `index.backup-<时间戳>.json`。

## 任务 3：提示词呈现换代（stickers.py + prompts.py）

1. `get_prompt_sticker_list()`：返回项从纯键名改为 `"名称（含义）"`——含义太长截断 15 字；无 meaning 的老数据回退纯键名（兼容）；
2. `SYSTEM_PROMPT_TEMPLATE` 与 `PROACTIVE_GENERATE_PROMPT` 的表情包行补一句：`表情包列表里括号内是它的含义，选择时按含义选；输出时 [sticker:] 里只写名称本身，不要带括号`；
3. `match_sticker` 不动（现有精确+子串匹配已能兜住"模型多带括号内容"的情况，已有测试覆盖）；
4. 新增测试：带 meaning 的列表格式、无 meaning 回退、提示词含新指引句。

## 任务 4：新收藏自动打标规则换代（prompts.py `STICKER_DESC_PROMPT`）

1. 现规则只产"15 字画面描述"，改为产出三栏 JSON（同任务 1 的三栏定义，名称仍 2~6 字）；
2. `stickers.py collect_sticker` 的解析链路同步：新格式写 meaning/usage 字段；解析失败/模型返回旧格式时**降级**为"名称+画面 desc"两栏旧行为（不炸、不丢收藏）；
3. 新增测试：新格式解析、旧格式降级、解析失败兜底。
